# 项目优化与一致性修复设计

**日期**：2026-02-03

## 1. 背景与目标
本次优化聚焦三类问题：
1) 中间件与安全链路未统一接入，生产与开发配置存在差异；
2) 统计接口与查询性能不足，缺少索引与缓存；
3) WebSocket/通知的生产级稳定性不足，前后端响应格式分支较多。

目标：
- 保持前后端功能一致性与接口闭环；
- 统一中间件与 CORS 逻辑，降低配置漂移；
- 提升统计与查询性能；
- 收敛前端 dataProvider 响应解析复杂度；
- 明确验证与回滚策略。

## 2. 范围与非目标
范围：
- 后端中间件接入、CORS 配置化；
- Redis 测试逻辑从主包剥离；
- WebSocket origin 校验与 webhook 并发/重试；
- 工单统计 SQL 合并、Redis 缓存；
- 新增 pg_trgm/GIN 索引；
- 前端删除测试页面、简化 dataProvider。

非目标：
- 不新增业务功能（如 WS 未读数/消息确认业务逻辑）；
- 不重构 UI 视觉样式；
- 不改动权限模型。

## 3. 总体方案
### 3.1 中间件统一接入
- 在 `server/main.go` 统一使用 `internal/middleware.SetupMiddlewares`。
- CORS 由 `config` 提供，移除手写 CORS 中间件以避免双重头设置。

### 3.2 WebSocket/通知稳定性
- WebSocket 升级时校验 Origin 白名单（生产严格、开发宽松）。
- Webhook 发送引入并发池 + 退避重试，限制并发与峰值；失败可观测。

### 3.3 统计与查询性能
- `GetTicketStatistics` 合并多次 `COUNT` 为单 SQL 聚合。
- Redis 短 TTL 缓存统计结果（按用户/角色/过滤条件拼 Key）。
- 数据库新增：
  - `pg_trgm` 扩展；
  - `tickets.title/description` trigram 索引；
  - `tickets.tags` GIN 索引。

### 3.4 前端一致性
- 删除 `web/src/TestApp.tsx`、`web/src/TestApp2.tsx`。
- `dataProvider` 统一优先解析标准响应格式，最小化兼容分支。
- 后端若调整响应结构，前端同步更新解析与类型。

## 4. 一致性策略
- 所有接口变更点建立“一对一”映射：后端变更 → 前端解析更新。
- 任何字段变更必须同步修改前端资源解析与使用处。
- 变更列表进入计划文档与验收清单。

## 5. 风险与回滚
- 中间件接入可能影响 CORS/限流行为；提供开关与环境变量回退。
- 索引创建可能影响迁移窗口；支持回滚迁移。
- Webhook 并发限制需合理参数，避免吞吐过低。

## 6. 验证策略
- 单测：`go test ./...`；前端：`npm run lint`。
- 行为验证：统计接口与列表查询结果一致；搜索/标签过滤正确。
- 性能验证：关键 SQL explain（若可）与缓存命中日志。
- 联调验证：登录→工单列表→筛选→统计→通知/自动化列表。

## 7. 回滚策略
- 中间件与 CORS 可回退为原手写中间件。
- 索引迁移提供 drop 脚本。
- Webhook 并发限制可回退为串行或无限制。
