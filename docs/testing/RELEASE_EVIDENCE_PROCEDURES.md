# ChronoDesk 发布前人工、Chrome 与故障注入证据规程

本文件只定义尚不能由现有自动化完整证明的发布门禁，不记录执行结果。执行人必须
把时间、提交 SHA、环境标识（不得含 DSN/Token）、步骤、实际结果和脱敏附件写入
当次测试报告。未执行、无附件或清理失败均不得标记为通过。

故障注入仅可在一次性 Docker/预发布环境中执行；禁止对共享云生产数据断网、停库、
灌入恶意文件或施加压力。Chrome 项使用 `E2E-<run-id>-` 数据，检查完逐项恢复高风险
开关并清理本轮资源。

## 基础设施、认证与 RBAC

| Case ID | 类型 | 可复现步骤与通过条件 |
|---|---|---|
| INF-001 | 故障注入 | 移除 PostgreSQL 配置后启动 API；进程必须非零退出，日志只能出现稳定配置键名，不得出现 DSN、密码或主机凭据。 |
| INF-002 | 故障注入 | 分别移除 Redis 配置、指向不可达端点；API 必须启动失败或健康状态 fail-closed，高风险写入不可绕过。 |
| INF-003 | 人工 | 对当前云 PostgreSQL 运行官方迁移命令，保存模型/索引/约束校验摘要及退出码，不保存连接串；如包含角色切换，另保存 `20260730_platform_roles_v1_cutover` 的 key、版本和 checksum 校验摘要。 |
| INF-004 | 人工 | 同一提交、同一云库连续运行两次完整迁移；第二次退出 0，模型行数与业务数据校验和不变，角色 checkpoint 不重复回填或重置后续 Membership。 |
| INF-008 | 故障注入 | 在有长连接和 Outbox worker 时发送 SIGTERM；新请求停止进入，后台任务在超时内结束，连接关闭且退出码正常。 |
| INF-009 | 人工 | 读取 `/healthz`，验证总状态、PostgreSQL、Redis 均为 `ok`，递归扫描响应不存在 URL、用户名、口令、Token。 |
| INF-010 | 故障注入 | 在一次性环境暂停 PostgreSQL 后执行读写；请求返回稳定 5xx，服务不 panic，恢复数据库后健康检查恢复且无假写入。 |
| INF-012 | Chrome | 浏览器时区设为 Asia/Shanghai，创建带时间的工单/通知；UI 显示本地时间，API 协议字段仍是带时区 RFC3339。 |
| AUTH-002 | 人工 | 逐个提交缺字段、非法邮箱、弱密码、边界外长度；每次均为中文 400，按唯一 marker 查询确认无用户残留。 |
| AUTH-003 | 故障注入 | 两个并发连接使用同一新邮箱注册；只允许一个成功，另一个为稳定 409，数据库只存在一行。 |
| AUTH-014 | 人工 | 修改 E2E 用户密码；旧 access/refresh 与旧密码全部失效，新密码登录成功，审计无密码内容。 |
| RBAC-001 | 人工 | 为 `member` 账号建立当前项目的显式 `project_admin` Membership；该账号修改另一项目成员创建的 E2E 工单，随后按事件/历史/审计读取，核对 Actor、版本和事件关联，并确认对未授权项目仍拒绝。 |
| RBAC-002 | 人工 | 为 `member` 账号建立当前项目的显式 `manager` Membership；该账号查看队列、分配和升级 E2E 工单，并尝试平台系统配置写入；前三者允许，平台管理必须 403。 |
| RBAC-008 | 自动化补充说明 | 四个平台角色在无 Membership 时分别访问项目入口和工作台，均不得获得隐式项目范围；再授予并撤销一个 active Membership，确认项目入口与工作台立即随之变化。真实 HTTP 证据见 manifest。 |
| RBAC-009 | 人工 | 用当前平台角色签发 Human 会话后，在受控环境改变该用户平台角色或停用身份；旧会话必须以稳定 `stale_token`/认证拒绝失效。恢复前后分别检查 JWT 不含项目角色，项目角色只由 active Membership 解析。 |
| RBAC-012 | 自动化补充说明 | Human 管理面以操作者、目标用户路径/ID、方法、结果、时间/来源和敏感 query 脱敏为契约；不把 Agent 写操作专属的 diff/event 字段强加给该接口。真实 HTTP 证据见 manifest。 |

## 工单、内容、自动化与事件

| Case ID | 类型 | 可复现步骤与通过条件 |
|---|---|---|
| TKT-016 | 人工 | 对 E2E 工单执行升级，核对优先级、处理人、原因、历史、CloudEvent 与新处理人通知一致。 |
| TKT-022 | 人工 | 创建标题含 `% _ ' 中文` 的 E2E 工单，按标题和编号搜索；只能返回匹配集合，错误排序字段不得成为 SQL 标识符。 |
| TKT-026 | 人工 | 创建含标签、Schema 合法自定义字段和客户信息的工单，更新后刷新详情；类型和值保持且中文标签正确。 |
| CNT-005 | 人工 | 创建父/子评论并并发回复，核对同工单约束与原子 reply_count；跨工单父 ID 必须拒绝。 |
| CNT-007 | 人工 | 上传零字节、上限+1、危险扩展、MIME/魔数不符文件；分别得到稳定 400/413/415，临时目录无残留。 |
| CNT-011 | 故障注入 | 两个连接用同一版本并发上传；只允许有效版本提交，失败方无附件行、对象或清理 Outbox 孤儿。 |
| CNT-012 | 人工 | 把已上传附件关联同工单评论后读取正式附件记录；尝试关联其他工单评论必须拒绝且原关联不变。 |
| AUT-013 | 人工 | 触发成功与失败规则后查看日志/统计；顺序、状态、耗时与脱敏错误必须与实际执行一致。 |
| AUT-014 | 故障注入 | 在规则值、字段和模板位置输入 SQL/模板注入载荷；只作为数据处理，不执行 SQL、模板函数或外部命令。 |
| EVT-005 | 人工 | 让受控 Webhook 连续失败至重试耗尽；delivery 进入 dead-letter，尝试次数、下一次时间和脱敏原因可观测。 |
| EVT-006 | 人工 | 管理员回放上述 dead-letter；产生新 attempt，原 CloudEvent `(source,id)` 不变且业务副作用不重复。 |
| EVT-009 | 人工 | 对企业微信、钉钉、飞书、Slack、Teams、custom 逐一生成超长 Unicode 消息；结构合法、按字符安全截断且无凭据。 |
| EVT-010 | Chrome | 在 Webhook 页面执行测试，确认中文反馈与日志状态一致；使用保留 `.invalid` 域名，不触达真实第三方。 |
| EVT-013 | 人工 | 两个用户分别更新通知偏好并重新登录；只改变本人设置，另一用户及既有通知不变。 |
| EVT-015 | 人工 | 以同一 correlation_id 完成工单写入、自动化与 Webhook；事件的 trace/correlation/causation 可从头到尾串联。 |
| EVT-017 | 人工 | 使用未认证、错误用户和合法收件人建立 WebSocket；前两者不得收到事件，合法连接只收到本人通知。 |
| AGT-024 | Chrome | 在 Agent 控制中心强制释放 E2E 租约并接管工单；旧 Agent 下一次写入失败，新 Actor/审计事件完整。 |
| MCP-013 | 人工 | 使用 MCP Inspector 读取不存在的 ticket/resource URI；返回当前协议的结构化 `-32602`，无内部路径。 |
| MCP-018 | 人工 | 发送合法与非法 traceparent/tracestate/baggage；合法值进入事件/审计，非法值被丢弃而非回显或信任。 |
| MCP-019 | 人工 | 通过 MCP 创建含提示注入文本的工单/评论；工具描述、Schema、策略决定不变，文本仅出现在不可信数据字段。 |
| MCP-020 | 故障注入 | 分别发送 body 上限+1、过深 JSON 和超过订阅上限的请求；得到 413/结构化限额错误，进程内存与 goroutine 有界。 |

## 安全、性能与恢复

| Case ID | 类型 | 可复现步骤与通过条件 |
|---|---|---|
| SEC-001 | 人工 | 对 search/filter/sort 输入 SQL 元字符并观察查询；结果稳定，排序仅白名单，数据库日志无拼接执行。 |
| SEC-006 | 故障注入 | 发送 JSON/multipart 上限+1及高压缩比附件；在限制处拒绝，RSS、临时文件与连接数回落。 |
| SEC-008 | 人工 | 在 TLS 预发布读取响应头和 Cookie；核对 CSP/HSTS/nosniff/frame policy/HttpOnly/Secure/SameSite。 |
| PERF-001 | 故障注入 | 预置 10k E2E 工单，测第一页查询计划与 P95；必须命中预期索引并低于发布门槛。 |
| PERF-002 | 故障注入 | 并发执行列表与 CAS 更新，记录 P95/错误率/连接池；跑 race，不能出现丢更新或池耗尽。 |
| PERF-003 | 故障注入 | 建立至上限及上限+1 WebSocket/MCP 订阅；超限明确拒绝，关闭后配额及时释放。 |
| PERF-004 | 故障注入 | 预置大量可重试 Outbox，启动 worker；批次有界、公平退避、最终清空且其他请求不饥饿。 |
| RES-003 | 故障注入 | 在业务事务中制造 PostgreSQL statement timeout；Ticket/历史/Event/Outbox 全回滚并记录安全错误。 |
| RES-006 | 人工 | 从脱敏备份恢复到新实例，运行迁移和凭据 validate；版本约束、密文和启动健康全部通过。 |
