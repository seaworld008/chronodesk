# 项目分析与架构文档

## 1. 项目概览
**ChronoDesk** 是一个现代化的支持工单平台，旨在高效管理客户支持工作流。它利用强大的技术栈（Go 后端 + React 前端），确保了高性能和可扩展性。

## 2. 功能分析

### 2.1 用户角色与权限
- **管理员 (Admin)**：拥有系统设置、用户管理和所有工单操作的完全访问权限。
- **客服 (Agent)**：可以管理工单、查看报表并处理分配的任务。
- **用户 (User)**：可以创建工单、查看自己的工单历史记录并与客服沟通。
- **身份验证**：
    - 基于 JWT 的无状态认证。
    - OTP（一次性密码）增强安全性。
    - 密码强度校验。
    - 可信设备管理。

### 2.2 工单管理
- **生命周期**：创建 -> 分配 -> 处理中 -> 已解决 -> 已关闭。
- **特性**：
    - 优先级和状态管理。
    - 分类（标签、类别）。
    - 内部备注和公开评论。
    - 附件支持。
    - 历史追踪（审计日志）。

### 2.3 自动化与规则
- **触发器**：基于工单事件（例如“新建工单”）自动执行操作。
- **动作**：分配给客服、发送邮件、更改状态、添加标签。
- **SLA 管理**：服务级别协议监控和警报。

### 2.4 通知系统
- **渠道**：邮件、Webhook、WebSocket（实时）。
- **模板**：可自定义的邮件和 Webhook 模板。
- **事件**：工单更新、分配、SLA 违规。

### 2.5 系统配置
- **通用设置**：系统名称、默认语言、时区。
- **邮件设置**：SMTP 配置、模板。
- **安全**：密码策略、会话超时。

### 2.6 分析与报表
- **仪表盘**：关键绩效指标 (KPI)、工单趋势。
- **报表**：客服绩效、工单量、解决时间。

## 3. 系统架构

### 3.1 后端 (`server`)
- **语言**：Go 1.21
- **框架**：Gin (Web 框架)
- **数据库**：PostgreSQL (主要数据存储), Redis (缓存和会话存储)。
- **ORM**：GORM。
- **结构**：
    - `cmd/`: 入口点。
    - `internal/`: 私有应用程序代码。
        - `models/`: 数据库模式和业务实体。
        - `handlers/`: HTTP 请求处理程序 (控制器)。
        - `services/`: 业务逻辑层。
        - `middleware/`: 认证、日志、CORS。
        - `config/`: 配置加载。

### 3.2 前端 (`web`)
- **语言**：TypeScript
- **框架**：React 18
- **构建工具**：Vite
- **UI 库**：React-Admin, MUI (Material UI), Shadcn/UI。
- **结构**：
    - `src/admin/`: 管理面板组件和页面。
    - `src/components/`: 可复用的 UI 组件。
    - `src/lib/`: 工具库、API 客户端 (`dataProvider`, `authProvider`)。
    - `src/types/`: TypeScript 定义。

### 3.3 基础设施
- **Docker**：容器化以便于部署。
- **Makefile**：自动化构建、测试和运行任务。
- **CI/CD**：GitHub Actions (由 `.github` 文件夹暗示)。

## 4. 代码结构分析

### 4.1 后端
后端遵循标准的 Go 项目布局 (Standard Go Project Layout)。
- **关注点分离**：处理程序、服务和模型之间有清晰的区分。
- **依赖注入**：服务可能被注入到处理程序中。
- **配置**：基于环境变量的配置 (`.env`)。

### 4.2 前端
前端使用 `react-admin`，它提供了一种结构化的方式来构建管理界面。
- **数据提供者 (Data Provider)**：将后端 API 适配为 `react-admin` 预期的接口。
- **认证提供者 (Auth Provider)**：处理登录、注销和权限检查。
- **基于资源**：页面围绕资源（工单、用户等）进行组织。

## 5. 优化建议

### 5.1 性能
- **数据库索引**：[已完成] 已为 `Ticket` (`Type`, `Priority`, `Status`, `Source`) 和 `User` (`Role`, `Status`) 模型添加索引。
- **缓存**：更广泛地利用 Redis 缓存频繁访问的数据，如系统配置和用户配置文件。
- **前端包大小**：[已完成] 已在 `vite.config.ts` 中配置 `manualChunks` 进行代码分割（vendor, ui, admin）。
- **查询优化**：[已完成] 审查 GORM 查询以避免 N+1 问题。修复了 `GetTicketStatistics` 中客服角色过滤失效的 Bug，并优化了 `EscalationService` 的定时任务循环结构。

### 5.2 代码质量与可维护性
- **测试**：
    - 增加 `services` 的单元测试覆盖率。
    - 为关键流程（工单创建、认证）添加更多集成测试。
    - 前端测试似乎很少；考虑添加 Cypress 或 Playwright 进行端到端 (E2E) 测试。
- **错误处理**：标准化所有 API 端点的错误响应。确保前端能优雅地处理这些错误。
- **类型安全**：确保前端有严格的 TypeScript 配置。如果可能，使用后端（生成）和前端之间的共享类型。
- **文档**：自动保持 API 文档 (Swagger) 的更新。
- **Lint 修复**：[已完成] 修复了后端服务中的 unnecessary fmt.Sprintf 和 loop 结构警告。

### 5.3 安全性
- **速率限制**：在 API 端点上实施速率限制以防止滥用。
- **输入验证**：在前端和后端都进行严格的验证。
- **依赖扫描**：定期扫描 Go 模块和 npm 包中的漏洞。
- **审计日志**：确保所有敏感操作（不仅仅是管理员操作）都被记录。

### 5.4 可扩展性
- **异步处理**：将繁重的任务（如发送邮件、复杂的自动化规则）移动到后台作业队列（例如使用 Redis streams 或专用队列系统），以避免阻塞 HTTP 请求。
- **无状态性**：确保后端保持无状态，以允许水平扩展。
