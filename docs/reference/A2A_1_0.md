# ChronoDesk A2A v1.0.1（线协议 1.0）

ChronoDesk 的 `/.well-known/agent-card.json` 和 `/a2a/v1` 仅实现 A2A
线协议 `1.0`。当前官方最新发布为 `v1.0.1`，补丁号不参与协议协商。

## JSON-RPC 连接约束

- 只接受 `POST /a2a/v1`。
- `Content-Type` 必须为 `application/json`。
- 每个请求必须通过 `A2A-Version: 1.0` 请求头或同名查询参数声明版本；
  两者同时出现时必须一致。A2A 规范要求服务端将缺失值解释为 `0.3`；
  ChronoDesk 不支持旧版本，因此会返回 `-32009 VersionNotSupportedError`。
- 只接受 A2A 1.0 的 PascalCase 方法：
  `SendMessage`、`SendStreamingMessage`、`GetTask`、`ListTasks`、
  `CancelTask`、`SubscribeToTask`、`CreateTaskPushNotificationConfig`、
  `GetTaskPushNotificationConfig`、`ListTaskPushNotificationConfigs` 和
  `DeleteTaskPushNotificationConfig`、`GetExtendedAgentCard`。
- 不提供 `message/send`、`tasks/get` 等 0.x 方法别名。
- 枚举采用 A2A 1.0 ProtoJSON 名称，例如 `ROLE_USER` 和
  `TASK_STATE_WORKING`；不接受小写旧值。
- 按 A2A 1.0 的前向兼容要求忽略真正未知的字段，但会显式拒绝已知旧字段、
  旧方法别名和大小写伪字段；未知字段不会进入策略、幂等摘要或响应回显。
- `Task`、`ListTasksResponse` 和 `TaskPushNotificationConfig` 只输出 A2A
  1.0 的标准字段。ChronoDesk 的关联工单 ID 位于标准
  `metadata["com.chronodesk/linkedTicketId"]`，不再使用顶层
  `linkedTicketId`；创建 Push 配置直接提交
  `TaskPushNotificationConfig`，不再接受嵌套 `config` 包装。
- `ListTasksResponse.totalSize` 是对象级授权过滤后的精确总数。
- 流式方法使用 SSE；`Last-Event-ID` 用于 ChronoDesk 的持久事件游标恢复。
- 对终态 Task 调用 `SubscribeToTask` 返回
  `-32004 UnsupportedOperationError`。未声明扩展卡能力时，
  `GetExtendedAgentCard` 同样返回 `-32004`；已声明但未配置时返回
  `-32007 ExtendedAgentCardNotConfiguredError`。
- A2A Push 请求使用 `Content-Type: application/a2a+json`，同时携带
  `A2A-Version: 1.0`；回调 URL 始终执行 HTTPS 与 SSRF 防护。
- OAuth token 请求必须携带精确的 RFC 8707
  `resource=${APP_URL}/a2a/v1`。MCP 或 REST API audience 的 token 会返回
  `401`，不会跨协议复用。
- A2A 资源发现入口为
  `/.well-known/oauth-protected-resource/a2a/v1`；Agent Card 的安全说明
  同时声明该 audience。

完整请求、响应及错误 Schema 以
[`/openapi.yaml`](../../server/internal/openapi/openapi.yaml) 为准。
