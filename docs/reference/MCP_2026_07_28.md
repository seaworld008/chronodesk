# ChronoDesk MCP 2026-07-28

ChronoDesk 的 `/mcp` 仅实现 MCP `2026-07-28`。它是无状态
Streamable HTTP 端点，不提供旧版 `initialize`、协议 Session、独立
GET SSE、DELETE、`Last-Event-ID` 或 `resources/subscribe`。

## 连接约束

- 只接受 `POST /mcp`。
- 每个请求都必须携带 `Authorization: Bearer ...`。
- `MCP-Protocol-Version` 必须为 `2026-07-28`。
- `Mcp-Method` 必须与 JSON-RPC `method` 一致。
- `Accept` 必须同时包含 `application/json` 与 `text/event-stream`。
- `tools/call` 和 `resources/read` 还必须发送与请求体一致的
  `Mcp-Name`。
- 每个请求的 `params._meta` 必须包含
  `io.modelcontextprotocol/protocolVersion` 和
  `io.modelcontextprotocol/clientCapabilities`。
- 使用无人值守客户端凭据的 Agent 应在每个请求的
  `io.modelcontextprotocol/clientCapabilities.extensions` 中声明
  `io.modelcontextprotocol/oauth-client-credentials: {}`。
- 不带 JSON-RPC `id` 的有效通知返回 HTTP `202`，响应体为空。
- 资源订阅使用同一 POST 上的 `subscriptions/listen` SSE；流不可恢复，
  断线后的可靠追赶使用 `/api/v1/events` 游标。
- 单个监听最多包含 64 个不重复资源 URI；活动监听默认限制为全局
  256、单服务主体 8、单凭据 4，超限返回 HTTP `429` 和
  `subscription_limit_exceeded`。
- 同一凭据的监听共享一个只读重校验器；凭据撤销、关键 scope 缩减或
  对象策略撤权会关闭对应监听。每条监听使用隔离的官方 SDK
  subscription server，事件发布前以无审计写入、无执行配额消耗的
  只读路径重新检查对象权限，再定向通知该监听。每条监听只有一个
  固定投递 worker 和容量 16 的 URI 去重队列，慢读客户端不会产生
  无界 goroutine 或向业务事务施加背压。

完整请求、响应及错误 Schema 以
[`/openapi.yaml`](../../server/internal/openapi/openapi.yaml) 为准。

## OAuth token

Token endpoint 只接受 `application/x-www-form-urlencoded`。RFC 8707
`resource` 必填，且必须精确等于部署配置的 canonical MCP URL：

```text
grant_type=client_credentials
client_id=<service-principal-client-id>
client_secret=<credential-secret>
scope=tickets:read events:subscribe
resource=https://chronodesk.example/mcp
```

该 token 的 `aud` 只允许 `/mcp`。它不能访问 `/api/v1` 或 `/a2a/v1`；
调用另外两个资源必须分别重新签发 token。JWT 的 `scope` claim 使用 RFC
9068 规定的空格分隔字符串。

发现入口为：

- `/.well-known/oauth-protected-resource/mcp`
- `/.well-known/oauth-authorization-server`

同一授权服务器还发布独立的 REST API 与 A2A 资源元数据：

- `/.well-known/oauth-protected-resource/api/v1`
- `/.well-known/oauth-protected-resource/a2a/v1`

`/oauth/token` 按可信客户端 IP 与路由独立限制为每分钟 30 次，不影响发现
元数据、Agent Card 或健康检查。

### OAuth Client Credentials 扩展

ChronoDesk 原生实现官方
[`io.modelcontextprotocol/oauth-client-credentials`](https://modelcontextprotocol.io/extensions/auth/oauth-client-credentials)
扩展，面向独立 `service_principal` 的无人值守调用，不引入人类授权码流程。
`server/discover` 会精确发布空配置对象：

```json
{
  "capabilities": {
    "extensions": {
      "io.modelcontextprotocol/oauth-client-credentials": {}
    }
  }
}
```

支持该扩展的客户端应在每一个 MCP 请求中声明，而不是只在发现请求中声明：

```json
{
  "_meta": {
    "io.modelcontextprotocol/protocolVersion": "2026-07-28",
    "io.modelcontextprotocol/clientCapabilities": {
      "extensions": {
        "io.modelcontextprotocol/oauth-client-credentials": {}
      }
    }
  }
}
```

扩展声明用于能力发现和互操作，不取代核心 Bearer 认证。资源服务器仍会在每次
请求中独立校验 token。客户端即使未声明该扩展，只要携带的 Bearer token
具有正确的 `iss`、`aud`、`exp` 和所需 `scope`，请求仍按核心授权规则处理。
当前凭据认证方式保持 `client_secret_basic` / `client_secret_post`，签发短期
token；不复用人类账号，也不接受面向其他资源的 token。

## MCP Inspector 2

Inspector 2 的临时 URL 模式默认仍可能尝试旧协议。必须显式配置
`protocolEra: "modern"`：

```json
{
  "mcpServers": {
    "chronodesk": {
      "type": "http",
      "url": "https://chronodesk.example/mcp",
      "protocolEra": "modern",
      "modernLogLevel": "off",
      "headers": {
        "Authorization": "Bearer ${MCP_TOKEN}"
      }
    }
  }
}
```

```bash
npx --yes @modelcontextprotocol/inspector@2.0.0 \
  --cli \
  --config ./mcp-inspector.json \
  --server chronodesk \
  --method tools/list \
  --format json
```

## 其他可选扩展

MCP Apps (`io.modelcontextprotocol/ui`) 和 MCP Tasks
(`io.modelcontextprotocol/tasks`) 不属于核心协议合规前置条件。ChronoDesk
当前未实现、也不会在 `server/discover` 中声明这两个扩展；A2A Task
与 MCP Tasks 是不同协议模型。
